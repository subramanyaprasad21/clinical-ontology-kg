# Inspecting the output in Protégé

Open `data/processed/review.ttl` for the asserted source union plus local ontology. Open `ontology/core/core.ttl` separately to review the small project vocabulary. The Turtle files use fully expanded IRIs and deterministic N-Triples-compatible syntax, which is valid Turtle.

Suggested checks:

1. Find `MONDO_0005148`; its direct named superclass is `MONDO_0005015` (diabetes mellitus).
2. Inspect the named hierarchy and the `skos:exactMatch` link to `https://omim.org/entry/125853`.
3. Inspect the three `kg:hasPhenotype` facts separately from `kg:hasInheritanceAnnotation` and `kg:hasClinicalModifier`.
4. Inspect the equivalent-class definition of `kg:PhenotypeAnnotatedConcept` and inverse relation on `kg:hasPhenotype`.
5. Compare `data/processed/inferred.ttl` with the asserted file. The materialized OWL RL results are generated by the code pipeline; a different Protégé reasoner may expose different bookkeeping results or apply different profile constraints to RDF metamodeling.
6. Use `data/processed/provenance.ttl` for record-level provenance. For named source context and authoritative SPARQL results, use the N-Quads dataset and `scripts/query.py` rather than flattening it in Protégé.

No manual editing is required to reproduce the project. Manual changes to generated files are overwritten by the next build. No automated or human Protégé session is represented as having occurred.
